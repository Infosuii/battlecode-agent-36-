# Agent 3 farming audit and experiment contract

Candidate source baseline for this audit: frozen bot_v34. Changes are independently OFF by default. No full-match strength claim is made by this document.

## Single-group pruning bound

Let R = gems + current gold_weight() * gold, and D0 = approach + weighted wait + capture_time + 4. For supported nonnegative game values and tuning, the actual cost is participants * (approach + wait + kill) + capture_time + 4 + drain >= D0: participants >= 1, kill >= 0, drain >= 0. Reward penalties for existing claims, recent enemies, territory, cohesion, buddy distance, initiating, siege and belief do not increase a nonnegative score.

The bound uses R / D0 multiplied by max(1,factor) for every potentially positive later term: target stickiness; the group's eligible runtime boot bonus; eligible dominant-group multiplier from its configured round; global positive altar bonus (conservative without a field read); nearby-number bonus; maximum deterministic jitter 1+abs(epsilon); and the enabled learner's declared maximum multiplier. Stickiness must be at least 1 in the bound even when runtime/compile tuning sets it below 1, because non-target groups receive no sticky discount. The runtime boot value is read directly, not inferred from APEX_BOOT_BONUS. A small float padding covers changed multiplication order. Invalid, negative, nonfinite or overflowing supported inputs conservatively return the largest finite float, disabling mathematical pruning for that group.

The bound applies to the final individual score, including optional learned residual and belief discount. It does not establish global route optimality. RouteK/RouteSlack candidate selection, 256-order capacity, 16 evaluated-group work cap and fuel exits remain separate approximations. Production does not lift these caps.

V36_FARM_DIAG reports considered, mathematically pruned, work-capped, evaluated and scored counts and traps when an actual final computed score is nonfinite or exceeds its admissible bound. V36_FARM_EXHAUSTIVE is diagnostic-only: it removes mathematical/work pruning and forces the single-group objective (no route search). It is unsuitable for release fuel measurements. Non-scoring eligibility and claim semantics remain in place.

Evidence: `agent3/test_farming.py` extracts the production score_groups function verbatim into a WASI fixture and supplies controlled observation/eligibility helpers. It compares matched pruned/exhaustive choices and asserts every computed final score against its bound across 25,000 randomized scenes plus a minimal regression. Covered dimensions include respawn/reward/alive states, rewards, claims/participants, 59/60-round boundary, current/noncurrent targets, 14.999/15-item boundary, runtime boot tuning, altar/numbers/jitter, enabled learned residual and positive/discount modifiers. This tests actual score code, not the official engine's observations or action semantics. The prior bound is also run to expose real counterexamples. `evidence/scorer-fixture.json` records current hashes and outcomes.

## Execution and fuel trace

The frozen first farm call has field_calls==0 and target_group==-1. With deterministic mode enabled, low_fuel is true and farm returns false before score_groups/route search. Distance fields are built at turn tail. Thus the supplied historical explanation that route depth two necessarily runs on round one is not established by this source. No round-one route skip was added.

Agent 2's governor API is integrated at score entry, before each group's expensive work even when no eligible best exists, before route work, before field ordering and before fields in deterministic and non-deterministic paths. Runtime probes cover init, scoring, route and fields. Existing gates/caps remain. Estimates (18k scorer entry, 4k/group, 20k route, 15k field ordering) are provisional and OFF by default until actual release measurements. A reserve policy is not a global fuel proof: mandatory work and prediction errors still need observed exhaustion/suspension evidence. No-best exits use the existing no-target/claim fallback; low-fuel farm entry retains the existing target if valid.

## Economy and camp findings

- go_home_if_needed preserves emergency retreat, health-limited spawn healing, healthy Tavi field-shopping exemption, an ongoing reward capture for a healthy rich champion, hot-zone evacuation before recall, recent-damage fallback, enemy/bush recall checks and walking fallback. These semantics have not been changed.
- tribute_if_needed distinguishes carried gems from submitted gems, avoids abandoning any capture underfoot for the early edge-bank rule, supports endgame/bag/distance triggers and safe altar routing. Raising/decreasing broad shopping/bank thresholds without measured opportunity loss is unjustified.
- camp_targets_me uses actual positions and range, nearest distance and lower-unit-ID tie breaking; a claim alone does not count as tanking there. allies_near_group uses a five-tile proximity/health threshold, so it can count helpers which have not arrived or do not currently tank. champions_needed additionally assumes hypothetical helper health. Those are model approximations requiring arrival traces.

## Farming loss ledger contract

For each identified artifact/map/side/match, store rounds 50/100/150/300 snapshots of submitted gems, carried gems, gold, deaths and completed collections. Keep first camp damage, final camp death/group clear, reward collection/capture completion, and gem submission as separate timestamps. Assign economic loss only from recorded events/state transitions, not from win labels or a mode name alone.

Time classifications must distinguish travel, respawn waiting/staging, camp fighting, reward capture, altar tribute, recall channel, spawn healing, shop actions and idle. Champion ability to attack/move can make categories overlap; retain primary mode and action/event flags instead of forcing every action into a mutually exclusive invented state. Camp-caused death needs killer/cause identity; linked partner death is a separate incident/body count. Death during camp mode alone is insufficient attribution. Claimed helpers and actual position/health/damage contributions remain separate.

Sample ladder incidents require platform submission/team metadata joins before being called v34 incidents. Historical tooling paths and numerical claims are unverified until reproduced. Strong varied opponent-pool calibration and unavailable external histories remain Agent 1/4 dependencies.

## Registered screen request

Hypothesis A3-BOUND: correcting the mathematical bound prevents losing the true best individual score while preserving explicit production work/route approximations. Principal ablation: same candidate build V36_FARM_BOUND=0 versus 1, all other new behavior switches equal. Primary full-match outcomes: paired win score and submitted-gem margin. Supporting: camp captures/timing, carried/submitted resources, candidate/pruned/work-cap counts, camp deaths, runtime skips/exhaustions/faults. Correctness acceptance requires zero fixture counterexamples and no unintended disabled-switch parity deviation. Screen acceptance additionally requires no material runtime regression and compatible paired-match evidence; no isolated-source test is treated as promotion proof.

Start with named stampede/rows/lanes/corners both-side development smoke; advance promising variants to Agent 1's frozen 200-map/400-game unseen schedule, varied recovered opponents and fresh validation. Expensive jobs use the shared compute queue. Broad economy, dense camp-safety, map-specific openings and optional farming ML stay unpromoted without evidence of their mechanism and full-match gains.
