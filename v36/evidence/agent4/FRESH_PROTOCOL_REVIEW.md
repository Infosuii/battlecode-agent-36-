# Pre-fresh protocol review

Reviewed `tools/fresh_protocol.py` version2 before any matching fresh protocol file/results existed. It declares only baseline, rows-cached and stack-cached alternatives; fixed numeric point/gem/fault/fuel gates; a deterministic fallback order; once-only selection; exact artifact identities; map sets and immutable protocol/schedule SHA receipts. Zero point/gem effects pass, equal exhaustion counts fail, and the fault rule applies to every completed fresh schedule. These are selection rules, not significance claims.

The declared grid is760 games: two40-map baseline head-to-heads(160), two10-map structural-shift heads(40),40-map stack-versus-rows(80), and three20-map/four-opponent/two-side pools(480). Each pool therefore has160 matched games per build, as stated in the event-count gate. All saved schedule grids, counts, candidate/opponent names and artifact hashes are explicitly validated before execution. Complete paired opponent/side strata stay together in map resampling. The freeze receipt is immutable on resume.

The governor event-count gate can prefer shorter games; it explicitly measures totals on the same160 games and does not claim equal champion-turn exposure or a worst-case reserve guarantee. Final reporting should retain duration/exposure caveats and native fault/fuel denominators separately from stage-attempt telemetry.

The primary validation maps share all ten generator dimension/pick/style templates with development, despite distinct seeds/hashes. The structural-shift validation uses clustered camps, adding a real mechanism shift; it still shares mirrored corner-spawn, wall and camp-placement machinery. Neither is proof of generalization across arbitrary competition map families. The local four-opponent pool is an uncalibrated substitute with actual names/hashes, not the historical seven-opponent pool. No final holdout file or performance was inspected for this review.

The paired comparison helper should verify the complete result-ID set and each artifact/map identity against frozen jobs rather than only result length and stratum keys. Root execution already checks full job completion; independent post-hoc parsing should retain the same identity checks.
